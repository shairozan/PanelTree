# Sprint 02 [MVP]: Recursive measure and constraint-based layout

## Outcome
Recursive measure and constraint-based layout.

## Queue
Sprint 02 of 19 · MVP. Take the lowest-numbered open issue whose title starts with `Sprint`. Complete its acceptance criteria before closing it and advancing. Sprint numbers express delivery order, not fixed calendar dates. No agent delegation is required by this ticket.

## Prerequisites
- Sprint 01: Project model, initialization, and strict YAML loading

## Scope
- Implement measure/layout passes producing immutable resolved scenes, with parent-assigned bounds and inherited context.
- Support nested rows/columns, weights, percentages, margins and gutters; allocate percentages after gaps and weights from the remainder.
- Define normalized layer frames, transforms, clipping, logical units, output-fit policies and shared pixel-edge rounding.
- Agree on an injected metadata/font measurement provider for later text rendering; layout performs no generation or network I/O.

## Acceptance criteria
- [ ] The 60/40 top row and three equal bottom panels resolve to asserted bounds.
- [ ] Mixed weights/percentages and nested layouts pass geometry tests; invalid/overconstrained inputs fail clearly.
- [ ] Resolution changes preserve geometry; differing aspect ratios require an explicit fit policy.
- [ ] Inspect prints resolved bounds; fake measurement verifies width-dependent text measurement.
- [ ] Implementation, relevant tests, and usage documentation are in the repository; report verification and remaining limitations before closing.

## Ownership boundaries
internal/layout/, scene/, inspect CLI and layout fixtures

## Out of scope
Pixel rendering, polygon panels, automatic narrative reflow.

## Architecture requirements
Go; command factories with invocation-local Viper and pointer-based pre-run initialization. CLI/MCP/web call shared application services. Composition drives renderer requests; stable project YAML remains backend-neutral. Preserve manual overrides and lock policy.
