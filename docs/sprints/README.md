# Sprint queue

All 19 sprint tickets are published as GitHub issues #1–#19. These local documents retain the detailed planning notes; GitHub issues are the authoritative execution queue. Published issue bodies include scope, acceptance criteria, ownership boundaries, exclusions and prerequisite links.

Take the lowest-numbered open GitHub issue whose title begins with `Sprint`. Keep one issue per sprint; implementation tasks belong in its checklist. Complete and verify its acceptance criteria before closing it. Sprint numbers define delivery order, not dates; actual issue numbers may differ when pull requests or other issues use GitHub's shared number sequence.

Sprints 01–09 deliver the local CLI/library/MCP MVP. Sprints 10–19 are the subsequent product roadmap. The existing scaffold is already complete and is not a new sprint.
