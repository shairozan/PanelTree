## Outcome
Revision-aware edits, approval, and scoped layer locks.

## Prerequisites
- Sprint 05: Content-addressed caching and incremental rebuilds

## Scope
- Implement shared typed changesets with expected revisions, complete validation before publication, and project write serialization.
- Add staged multi-file edits/recovery and explicit draft/review/approved transitions.
- Implement durable approval pins, manual overrides, and asset/placement/all lock scopes across CLI and application services.
- Enforce locks against indirect ancestor changes, deletion and source replacement; keep protected blobs outside disposable cache.

## Acceptance criteria
- [ ] Two writes at the same revision conflict without lost edits; recovery yields a complete old or new revision.
- [ ] Changed requests leave approved artwork selected and report stale provenance.
- [ ] Missing/corrupt pinned artifacts fail without generation; manual override files are never written.
- [ ] Source and placement locks work separately, plain lock means all, and explicit unlock is required before protected changes.
- [ ] Implementation, relevant tests, and usage documentation are in the repository; report verification and remaining limitations before closing.

## Ownership boundaries
internal/workspace/, internal/asset/, app/ editing/state operations and CLI

## Out of scope
GUI controls and multi-user identity/authentication.

## Architecture requirements
Go; command factories with invocation-local Viper and pointer-based pre-run initialization. CLI/MCP/web call shared application services. Composition drives renderer requests; stable project YAML remains backend-neutral. Preserve manual overrides and lock policy.
