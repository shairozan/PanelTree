# Sprint 08 [MVP]: Local MCP server and agent authoring workflow

## Outcome
Local MCP server and agent authoring workflow.

## Queue
Sprint 08 of 19 · MVP. Take the lowest-numbered open issue whose title starts with `Sprint`. Complete its acceptance criteria before closing it and advancing. Sprint numbers express delivery order, not fixed calendar dates. No agent delegation is required by this ticket.

## Prerequisites
- Sprint 07: Durable jobs and revision-safe asset requests

## Scope
- Ship paneltree mcp serve with local stdio transport using shared application services, not shell-command wrappers.
- Expose project list/init/open/inspect/validate/apply_changes, renderer discovery/asset requests, builds/jobs/cancel, state/lock operations and available exports.
- Provide typed results, stable IDs, revisions, readable resources and client-consumable artifact/preview access.
- Enforce configured roots including symlink resolution; isolate credentials/runtime configuration and keep protocol stdout clean.

## Acceptance criteria
- [ ] A real MCP test client initializes a book, edits layers, requests a local asset, builds and retrieves a preview.
- [ ] MCP and CLI produce equivalent content for the same revision.
- [ ] Stale edits, lock bypass attempts, unavailable generators and out-of-root paths are rejected through shared rules.
- [ ] Transport startup, tools/resources, polling, errors and cancellation are integration-tested without ComfyUI.
- [ ] Implementation, relevant tests, and usage documentation are in the repository; report verification and remaining limitations before closing.

## Ownership boundaries
internal/mcp/, internal/cli/ MCP commands, MCP integration fixtures

## Out of scope
Hosted MCP, web UI, embedded story-planning model.

## Architecture requirements
Go; command factories with invocation-local Viper and pointer-based pre-run initialization. CLI/MCP/web call shared application services. Composition drives renderer requests; stable project YAML remains backend-neutral. Preserve manual overrides and lock policy.
