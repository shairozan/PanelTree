# Sprint 05 [MVP]: Content-addressed caching and incremental rebuilds

## Outcome
Content-addressed caching and incremental rebuilds.

## Queue
Sprint 05 of 19 · MVP. Take the lowest-numbered open issue whose title starts with `Sprint`. Complete its acceptance criteria before closing it and advancing. Sprint numbers express delivery order, not fixed calendar dates. No agent delegation is required by this ticket.

## Prerequisites
- Sprint 04: SVG, lettering, and portable editable exports

## Scope
- Separate asset production, placement/composition and export nodes in a dependency graph.
- Implement canonical recipe keys and output content hashes, immutable blobs, integrity checks and atomic publication.
- Hash relevant bytes, renderer versions, fonts, context and resolution; ignore comments, mapping order, timestamps and machine paths.
- Add build explanations and explicit draft revision/seed semantics; moving a source layer should reuse its artwork.

## Acceptance criteria
- [ ] An unchanged build performs zero leaf renders and zero recompositions.
- [ ] Moving a character only recomposites ancestors; dialogue changes rerender lettering and ancestors.
- [ ] A shared asset change rebuilds all dependent pages and no unrelated branches.
- [ ] Version/font changes invalidate relevant nodes; comments do not. Corruption and interrupted publication are tested.
- [ ] Implementation, relevant tests, and usage documentation are in the repository; report verification and remaining limitations before closing.

## Ownership boundaries
internal/cache/, internal/build/, render dependency contracts

## Out of scope
Approved pins, distributed caching, GPU reproducibility claims.

## Architecture requirements
Go; command factories with invocation-local Viper and pointer-based pre-run initialization. CLI/MCP/web call shared application services. Composition drives renderer requests; stable project YAML remains backend-neutral. Preserve manual overrides and lock policy.
